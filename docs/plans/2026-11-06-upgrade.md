# Updates: notice and `atticdb upgrade` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tell people when a new AtticDB release is out, and give them 1 safe command to install it.

**Architecture:**
- `/healthz` reports the server's version, and doctor flags a server older than the binary.
- A new `update` module reads the latest release tag at most once every 24 h. It uses the system `curl` and a cache file in the home.
- Doctor and setup print 1 notice line.
- `atticdb upgrade` keeps the old binary as `atticdb.prev`. It runs the release's own `install.sh`, pinned to the new version and to this binary's folder. Then it stops the running server and runs doctor.

**Tech Stack:** Rust, `crates/atticdb`, the system `curl` and `sh`. Tests in `crates/atticdb/tests/it/` use a fake release server on 127.0.0.1.

**Spec:** issue #173. Its 2 open questions are ruled here:
- Download and checksum: reuse `install.sh`. It already takes `ATTICDB_VERSION`, `ATTICDB_INSTALL_DIR` and `ATTICDB_DOWNLOAD_BASE`, and checks `SHA256SUMS`. No new crate.
- Package managers: detect them by the binary's path, and point to their own command.

## Global Constraints

- **Never check in the hot path.** No network call in `hook`, `mcp` or `serve`, or in any verb besides `doctor`, `setup` and `upgrade`.
- **Off switches.** `ATTICDB_NO_UPDATE_CHECK=1`, or `CI` set to any value. Builds whose version ends in `+dev` never print the notice.
- **Check.** `curl -fsSL --max-time 3 <api>`, where `<api>` is `ATTICDB_RELEASES_API`, default `https://api.github.com/repos/Clawdlinux/atticdb/releases/latest`. Read `tag_name`. Any failure is silent: no notice, and no error line, except in `upgrade`.
- **Cache.** `<home>/update-check.json` holds `{"checked": <unix seconds>, "latest": "<tag without v>"}`, written atomically. It's reused for 24 h.
- **Notice.** Exactly: `AtticDB <latest> is out (you have <current>). Run: atticdb upgrade`. Only when `latest` > `current` by semver.
- **`atticdb upgrade [--yes] [--version <v>]`:**
  - The plan lines come first: from, to, `https://github.com/Clawdlinux/atticdb/releases/tag/v<to>`, and the warning `If this release changes the store format, the previous binary can't open the store after the first write.`
  - It asks `Upgrade? [y/N]` unless `--yes`. With no terminal and no `--yes`, it refuses with exit 2.
  - Downloads `<ATTICDB_DOWNLOAD_BASE or https://github.com/Clawdlinux/atticdb/releases>/download/v<to>/install.sh` with curl to a temp file.
  - Copies the binary to `<exe>.prev`. Runs `sh <temp>` with `ATTICDB_VERSION=<to>` and `ATTICDB_INSTALL_DIR=<exe's dir>`, plus `ATTICDB_DOWNLOAD_BASE` when set.
  - If the installer fails, the binary is left as it was, and `.prev` is removed.
  - On success, it stops the server whose pid is in `<data>/LOCK` with SIGTERM, then waits up to 5 s for the lock to free. It ends by running doctor.
- **Install methods.** A binary under `~/.cargo/bin` gets `Installed by cargo. Run: cargo install --git https://github.com/Clawdlinux/atticdb atticdb --locked`. One under `/opt/homebrew` or `/usr/local/Cellar` gets `Installed by Homebrew. Run: brew upgrade atticdb`. Neither runs anything.
- **Windows.** `upgrade` prints the manual steps from the README, and exits 1.
- **Writing and commits.** No em dashes, sentences under 20 words. Commits use `git commit -s`, with no Co-authored-by.
- **Verify.** `cargo fmt --all --check`, `cargo clippy --locked --workspace --all-targets --all-features -- -D warnings`, `cargo clippy --locked --workspace -- -D warnings`, `cargo test --locked -p atticdb`.

## Review Focus

1. **Installer fails mid-way.** The binary in place is unchanged, and the server keeps running. Test: `upgrade_keeps_binary_when_installer_fails` (Task 3).
2. **Offline or GitHub down.** Doctor and setup print no notice and no error, and still finish fast. Test: `doctor_quiet_when_check_fails` (Task 2).
3. **No terminal and no `--yes`.** `upgrade` never installs. Test: `upgrade_needs_yes_without_terminal` (Task 3).
4. **Cached latest is not newer.** No notice, even when the cache is fresh. Test: `no_notice_when_current` (Task 2).
5. **The hook and `mcp` never touch the network.** Test: `hook_never_checks` (Task 2). Run the hook with `ATTICDB_RELEASES_API` pointing at a listener that fails the test if contacted.

## What this plan does not do

- No automatic update and no `update = "auto"` setting.
- No studio banner, and no notice in other CLI verbs. Doctor and setup are enough to start.
- No Windows self-update. It prints the manual steps.
- No store format version in the release metadata. The format warning is always shown.
