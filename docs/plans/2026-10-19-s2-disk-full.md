# S2: disk full. Implementation plan

> For agents: one implementer on branch `feat/s2-disk-full`, TDD, one commit per task. Then two independent reviews (Claude Opus 5.5 and Gemini 4 Argon) before merge.

**Spec:** `docs/design/0003-slim-v0.1.md`, invariant I14 and section "S2". Decision D71 in `0002-decision-log.md` (`rustix` replaces D34).

**Goal:** a full disk never loses an acknowledged write. Below a free-space floor the engine rejects writes cleanly with `DiskFull` and `NotCommitted`, keeps serving reads, reports read-only health, and accepts writes again once space returns. Real storage errors during a write still poison, as today.

## T1: Io space and preallocation

- Add to the `Io` trait: `available_bytes(dir) -> Result<u64>` (bytes an unprivileged writer can use, from `f_bavail * f_frsize`) and `total_bytes(dir)`, and `allocate(file, len) -> Result<()>` (reserve real blocks, then make the file length `len`).
- `StdIo`:
  - Linux: `fallocate` mode 0.
  - macOS: `F_PREALLOCATE` (try contiguous, then any), then `set_len`, because `F_PREALLOCATE` does not move the end of file.
  - If `rustix` has no safe preallocation call for a platform, fall back to `set_len` there and say so in a doc comment. On copy-on-write filesystems (APFS, btrfs) preallocation is not a guarantee anyway. The floor is the guard.
- Sim `Io`: a configurable capacity. Writes and allocations past it fail with `StorageFull`. Space can be freed during a run.
- `DataDir::prepare_next_segment` uses `allocate` instead of bare `set_len`.
- Tests: allocation reserves space in the sim, `available_bytes` drops by the segment size, `StorageFull` from `allocate` leaves no manifest change.

## T2: the free-space floor

- `TapeOptions::free_space_floor: Option<u64>`. `None` means the default: the smaller of 1 GiB and 5% of `total_bytes` at open.
- Checked in the writer step, once per group, before any `prepare`. The check needs: batch bytes for the group, plus a whole new segment if the group will not fit in the current one.
- Below the floor: every request in the group gets `DiskFull` with `NotCommitted`. Nothing is prepared, written, published or poisoned. Sequence numbers, dedup state and session state are untouched.
- If the group needs a new segment and there is room, pre-roll it before `prepare`, so a roll never fails halfway through a write.
- Expose `read_only()`: true while the last floor check failed. It clears on the next passing check.
- `statvfs` is one syscall per group. Keep it off the per-request path.
- Tests: clean floor hit does not poison; state unchanged after rejection (reopen shows the same LSNs and txns); writes resume after space is freed; a group that needs a roll is rejected as a whole when the roll would cross the floor.

## T3: engine and health

- The engine passes `DiskFull`/`NotCommitted` through unchanged. Reads keep working while read-only.
- Add `Engine::health() -> Health { Ok, ReadOnly, Poisoned }`. S3 maps it to `/healthz`.
- Idempotency: a request rejected by the floor and retried later with the same `idem_key` writes normally. It is not deduplicated against a write that never happened.
- Tests: engine reads during read-only; retry with the same key after space returns commits once; `health()` transitions Ok to ReadOnly to Ok.

## T4: sims

- Tape sim and engine sim: add a disk-capacity fault. Random capacity limits, random frees, and real `StorageFull` during writes and syncs.
- Oracles: no acknowledged write lost; a clean floor hit never poisons; a real write or sync error still poisons, and recovery after it is clean; state after a rejected group equals state before it.
- 2,000 seeds in CI style. 10,000 once locally per sim.
