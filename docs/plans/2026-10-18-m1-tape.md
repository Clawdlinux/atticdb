# zerodb M1: tape, I/O, recovery. Implementation plan

> For agents: execute with subagent-driven development. One implementer per task group, then spec review, then quality review. TDD for every task.

**Goal:** a crash-safe append-only tape with group commit, recovery, and a deterministic fault-injecting disk. This is the base every later milestone builds on.

**Architecture:** see `docs/design/0001-architecture.md` sections Tape, Frames, Writer thread, Durable boundary and recovery, Segment roll, Fsync failure, Deterministic simulation. Decision ids D1, D8-D11, D19, D25, D26, D34, D40-D42, D46 apply.

**Tech:** Rust stable, edition 2021, MSRV 1.89. Crates allowed in M1: `blake3` (digests and chain), `proptest` and `criterion` (dev only). Nothing else. CRC32C is written here.

**Crate:** `crates/zerodb-tape` (library). Public API kept small. `#![forbid(unsafe_code)]`.

**Commands:** `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`. All must pass before each commit. Commits use `git commit -s`, conventional messages, and the trailer `Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>`.

**Budget:** about 3K lines of Rust excluding tests for all of M1.

## Group A: primitives

### A1. CRC32C

- File: `src/crc32c.rs`. Castagnoli polynomial `0x82F63B78`, reflected, slicing-by-8 tables built in a `const fn`.
- API: `pub fn crc32c(data: &[u8]) -> u32` and an incremental `Crc32c` with `update` and `finish`.
- Tests first: `crc32c(b"123456789") == 0xE306_9283`. Empty input is 0. Incremental over random splits equals one-shot (proptest). 32 bytes of zeros equals `0x8A91_36AA` (RFC 3720 B.4).

### A2. Io and Clock traits

- File: `src/io.rs`.
- `trait Io: Send + Sync` with: `create(path) -> FileId`, `open(path)`, `write_at(file, off, &[u8])`, `read_at(file, off, &mut [u8]) -> usize`, `len(file)`, `set_len(file, n)`, `sync_data(file)`, `sync_dir(dir)`, `rename(from, to)`, `remove(path)`, `list(dir)`, `exists(path)`, `try_lock_exclusive(path) -> Result<LockGuard>`.
- `StdIo` implements it with `std::fs`. `sync_data` uses `File::sync_data`. `sync_dir` opens the dir and calls `sync_all`. Lock uses `File::try_lock`.
- `trait Clock: Send + Sync { fn now_ns(&self) -> u64; }`. `SystemClock` and `SimClock` (manually advanced, shared via `Arc`).
- Errors: a crate `Error` enum with `Io(std::io::ErrorKind, String)`, `CorruptionDetected { lsn, segment, offset, reason }`, `DataDirLocked { holder: String }`, `Poisoned`, `DiskFull`, `BatchTooLarge`, plus whatever later tasks need. No `unwrap` outside tests.

### A3. SimDisk

- File: `src/simdisk.rs`. Deterministic, seeded (`u64` seed, own xorshift or splitmix PRNG, no `rand` crate).
- Model: each file has `durable: Vec<u8>` and a list of pending unsynced writes. Directory has durable entries and pending entries (create, rename, remove).
- `sync_data(file)` makes that file's pending writes durable. `sync_dir` makes pending entries durable.
- `crash()` returns a new SimDisk image where, for each file, a random subset of pending writes is applied in random order, and each applied write may be torn at a random byte. Pending dir ops are randomly applied or dropped, but a rename is atomic (old or new, never both, never neither).
- Fault knobs: `fail_next_sync`, `enospc_after_bytes` (partial write then `StorageFull`), `flip_bit(file, offset)` on durable data.
- Tests first: synced data survives every crash seed (1,000 seeds). Unsynced write survives some seeds and is lost or torn in others. Rename crash yields exactly one name. `fail_next_sync` returns an error and leaves data pending. Same seed gives the same result.

### A4. Frames, digests, chain

- File: `src/frame.rs`. Layout from 0001 Frames, little-endian:

```text
u32 crc32c(over bytes [4..len_total))
u32 len_total (header + payload) | u8 kind | u8 version | u16 flags
u64 txn | u64 lsn | u64 commit_time_ns
u32 tenant_id | [32] tenant_prev_chain | [32] content_digest
payload
```

- Kinds for M1: `Turn = 1`, `Fact = 2`, `Cache = 3`, `Redaction = 4`, `Footer = 5`. Footer payload: `u64 txn | u32 record_count | [32] batch_digest`.
- `content_digest = blake3(salt16 || content)` where the salt is the first 16 payload bytes. Footer and Cache use an all-zero chain field. `flags` bit 0 = husk (payload absent).
- `canon(header) = kind | version | txn | lsn | commit_time_ns | tenant_id` (fixed little-endian, 30 bytes).
- `chain_next(prev, header, digest) = blake3(prev || canon || digest)`.
- `batch_digest = blake3(concat of content digests)`.
- `encode(&Frame) -> Vec<u8>`, `decode(&[u8]) -> Result<(Frame, usize), DecodeError>` where `DecodeError` is `EndOfData` (len 0), `Truncated`, `BadCrc`, `BadLength`, `UnknownVersion`.
- Tests first: round trip (proptest). Any single bit flip anywhere in the frame gives `BadCrc` or `BadLength`. A husk of a frame produces the same `chain_next` as the original. `len_total == 0` gives `EndOfData`. Max frame size 4 MiB enforced.

## Group B: tape files and writer

### B1. Data dir files

- File: `src/dir.rs`. `LOCK` (holds PID and optional server address as text), `MANIFEST`, `SUPERBLOCK`, segments `seg-{:016}.zdb`.
- Atomic install helper: write `X.tmp`, `sync_data`, `rename` to `X`, `sync_dir`.
- `MANIFEST` v1: magic, version, list of segment ids, CRC32C trailer. `SUPERBLOCK` v1: magic, version, `durable_lsn`, CRC trailer.
- `open_dir` takes the lock first. Second opener gets `DataDirLocked` with the holder text.
- Tests first: install survives crash at every SimDisk point (old or new content, never a mix). Lock contention in the same process with `StdIo` and a temp dir.

### B2. Segment pre-creation and roll

- Segment size 64 MiB (configurable for tests, e.g. 64 KiB).
- `prepare_next_segment`: create, `set_len`, `sync_data`, `sync_dir`, add to `MANIFEST` via atomic install. The writer switches only to a prepared segment. In M1 this runs inline on the writer when needed, recorded as an M2 follow-up to move to a background task.
- A transaction never spans segments. If a batch does not fit, roll first.

### B3. Writer and group commit

- File: `src/writer.rs`. `Tape::open(io, clock, dir, opts) -> (Tape, RecoveryReport)`.
- `Tape::append(batch: Vec<RecordInput>, mode: Durability) -> Result<Committed, WriteError>`. `RecordInput { kind, tenant_id, content: Vec<u8> }`. Caller-side code computes salt and digest before enqueue (D26).
- A single writer thread owns the active segment. Callers send `(batch, oneshot)` over `std::sync::mpsc`. The writer drains every queued batch, assigns txn and LSNs, frames them with chains per tenant, writes each batch plus its footer, then `sync_data` on every file written since the last sync (D40), then publishes `durable_lsn` and replies.
- `Committed { txn, first_lsn, last_lsn }`. `WriteError { kind, outcome: Committed | NotCommitted | Unknown }` (D38).
- Durability `Fast` (cache only): reply after write, before sync. The reply carries no LSN (D46). Fast records become durable at the next sync.
- Sync failure: every in-flight batch gets `outcome: Unknown`, the tape becomes `Poisoned`, later appends get `NotCommitted`.
- Batch limits: 4 MiB or 1,024 records, else `BatchTooLarge` with `NotCommitted`.
- A background superblock updater (M1: called by the writer at most once per second after a successful sync, using the atomic install) records `durable_lsn`.
- `Tape::read(lsn)` for tests and later views: returns the frame for a durable LSN via an in-memory `lsn -> (segment, offset)` map built during append and recovery. Only LSNs at or below `durable_lsn` are visible (D12).
- Tests first: concurrent appends from 8 threads get dense unique LSNs in commit order. A batch is all or nothing. Sync failure yields `Unknown` then `NotCommitted`. Fast append returns no LSN. Group commit: with a slow `sync_data` in a test Io, many concurrent appends share one sync (count syncs).

### B4. Recovery

- File: `src/recovery.rs`. On open: read `MANIFEST`, `SUPERBLOCK`, scan segments in order.
- Rules (0001 Durable boundary and recovery, D8, D41):
  - At or below the superblock LSN: any decode error, `EndOfData`, or missing manifest segment gives `CorruptionDetected`.
  - Above it: stop at the first decode error or the first transaction with no valid footer. Truncate the segment logically there (zero-fill the remainder and sync before accepting writes). Report the truncated LSN range and bytes.
  - LSNs must be strictly increasing. Gaps are allowed (later compaction). Chains must verify per tenant for every record, husks included.
- `RecoveryReport { durable_lsn, truncated: Option<(lsn_range, bytes)>, segments, records }`.
- Tests first: clean reopen. Torn tail truncated. Bit flip below superblock gives `CorruptionDetected`. Missing segment below superblock gives `CorruptionDetected`. Footer missing on the last txn drops it. Crash during a group spanning a roll keeps every acked record.

## Group C: simulation, stress, bench

### C1. Simulation harness

- File: `tests/sim.rs` plus `src/sim.rs` behind `#[cfg(any(test, feature = "sim"))]`.
- Single-threaded seeded driver: the writer runs as a step function in sim mode (a `WriterCore` with `enqueue` and `step` that the thread loop also uses). This is the D25 requirement: same core, two drivers.
- Each seed: random workload (tenants, batch sizes, fast and durable), random sync failures, random crash point, then reopen on the crashed image.
- Invariants: every acked durable record is present and byte-identical; no partial transaction visible; every tenant chain verifies; LSNs strictly increase; recovery never errors except when a bit flip below the superblock was injected (then it must error).
- CI: 500 seeds per `cargo test`. `ZERODB_SIM_SEEDS=N` env for nightly. Failure prints the seed.

### C2. Real-thread stress

- `tests/stress.rs`: `StdIo` on a temp dir, 16 threads, 20K appends, random sizes, then reopen and check every acked record. Run under `cargo test --release` in CI.

### C3. Bench baseline

- `benches/append.rs` with criterion: (a) bare `write_all` plus `sync_data` of the same bytes, (b) `Tape::append` durable, 1 and 16 concurrent writers, 256 B and 4 KiB records. Report p50 and p99 per op. This is the G1 harness skeleton. The real G1 run is on Linux NVMe and is not part of M1 acceptance.
