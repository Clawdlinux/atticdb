# CLI help, errors and the logo. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- A wrong command prints 1 line saying what was wrong, plus that command's usage. Today it dumps all 60 lines.
- `atticdb --help` shows the site's logo in color and the commands in groups.

**Architecture:**
- A new library module, `crates/atticdb/src/cli.rs`, holds pure functions: color detection, the logo, the help screen and the error message.
- `main.rs` calls them where it prints `USAGE` today.
- `USAGE` moves to `cli.rs` unchanged and becomes `atticdb help --all`.

**Tech Stack:** Rust std only (`std::io::IsTerminal` and ANSI escape codes). No new dependencies.

**Spec:** this plan's Design section, approved by the owner on 2026-11-09 and 2026-11-10.

## Design (approved)

- **Logo.**
  - It's generated from `atticdb-mark.svg` in the website repo, viewBox 64x64. The roof is the polygon `32,3 63,30 55,38.5 32,19 9,38.5 1,30`. The box is the rect `x 19..45, y 39..61`.
  - Rendered at 16 columns and 8 rows with half blocks:

```
       ▄▄
     ▄████▄
   ▄███▀▀███▄
▄████▀    ▀████▄
 ▀▀▀        ▀▀▀
     ██████
     ██████
     ▀▀▀▀▀▀
```

  - Rows 1 to 5 are the roof, in cream `#EDE6D8`. Rows 6 to 8 are the box, in lime `#C8F03C`.
  - Beside rows 2 to 4, the header prints:
    - `atticdb <version>`, with `atticdb` bold lime
    - `local memory for coding agents`
    - `https://atticdb.com`
- **Color is on only when** the stream is a terminal, `NO_COLOR` is unset or empty, and the OS isn't Windows.
  - With `COLORTERM` set to `truecolor` or `24bit`, colors are 24-bit (`38;2;r;g;b`).
  - Otherwise they're 256-color: cream is 254 and lime is 191.
  - With color off, the logo is skipped. The header is 1 plain line: `atticdb <version>, local memory for coding agents`.
- **`atticdb`, `atticdb --help`, `-h` and `help`** print the help screen to stdout and exit 0. That's the header, then:

```
  Get started
    setup            find your agents and connect them
    connect <app>    connect 1 app
    doctor           check the install

  Memory
    search  recent  append  fact  tree  file  forget  export  studio

  Server
    serve  init  stats  verify  dump  recover  load  upgrade

  Every flag: atticdb help --all
```

  - Section headings are bold. Command names are lime.
  - `atticdb help --all` prints today's `USAGE` text unchanged, to stdout, and exits 0.
- **Errors go to stderr with exit 2.**
  - The first line is `error: <what>`, with `error:` in bold red when stderr has color.
  - Next comes `  usage: ` followed by that command's lines from `USAGE`.
  - The last line is `  more:  atticdb --help`.
  - `<what>` comes from the first rule that applies:
    1. `unknown command "<x>"`. Here the usage part is left out.
    2. For `connect` or `disconnect`: `unknown app "<x>"`. Then a line `  apps:  ` with the 7 names, separated by 2 spaces, in `Harness::ALL` order.
    3. `unknown flag "<--x>"`. The first `--` argument that isn't in that command's usage lines. A line containing `<connect>` also counts the `<connect>:` block's flags.
    4. `missing or invalid arguments for "<command>"`.
- **No change** to `atticdb mcp`, `atticdb hook`, JSON output or any other stdout protocol.
- **`atticdb setup`** prints the header (logo included when color is on) once, before its plan, when stdout is a terminal.
- **Windows** stays plain.
- **Not in scope:** per-command `--help` pages, "did you mean", and color in `doctor` or `setup` lines.
- **Added in the final review:** `help`, `--help` or `-h` with extra arguments prints the help screen. `help --all` still prints `USAGE`. `<command> --help` or `-h` prints that command's usage lines to stdout and exits 0. `connect` adds the apps line. `mcp` and `hook` are unchanged. Error messages quote argv with Rust Debug quoting, so control bytes are escaped.

## Global Constraints

- No new dependencies.
- No ANSI byte ever goes to a non-terminal. `mcp`, `hook` and every JSON line stay byte-identical.
- `USAGE` text is unchanged. It moves, and `help --all` prints it.
- `--version` keeps its output and exit codes. `--version extra` still exits 2, and stderr still contains `atticdb --version | -V`.
- Prose: no em dashes, sentences under 20 words, numbers as digits. Commits: `git commit -s`, no Co-authored-by.

## Review Focus

1. **`NO_COLOR=1` in a terminal** gives no escape bytes. Unit test in Task 1.
2. **Piped output** (tests run without a TTY) has no `\x1b` in help or errors. Test in Task 2.
3. **`atticdb connect claude-desktp`:** the first stderr line is `error: unknown app "claude-desktp"`, and an apps line lists `claude-desktop`. Test in Task 2.
4. **A typo in a `<connect>` flag**, such as `atticdb search --url-x u --query q`, gives `unknown flag "--url-x"`. And `--url` itself is accepted as known. Unit test in Task 1.
5. **`atticdb mcp` stdout** still begins with JSON-RPC, never a logo. The existing MCP tests cover it. Task 2 must not touch `mcp` or `hook` paths.

**Interfaces:**
- Produces:
  - `pub const USAGE: &str`, the existing text, unchanged
  - `#[derive(Clone, Copy)] pub enum Style { Plain, Ansi256, TrueColor }`
  - `pub fn style(is_terminal: bool, no_color: Option<&str>, colorterm: Option<&str>, windows: bool) -> Style`
  - `pub fn style_for(stream: &impl std::io::IsTerminal) -> Style`, which reads `NO_COLOR`, `COLORTERM` and `cfg!(windows)`
  - `pub fn header(style: Style, version: &str) -> String`, the logo and text, or the 1 plain line
  - `pub fn help(style: Style, version: &str) -> String`, the header plus the 3 groups and the footer
  - `pub fn error(style: Style, args: &[String]) -> String`, the full stderr text for a failed parse of `args`, which is argv without the program name
  - `pub const APPS: [&str; 7]`, taken from `Harness::ALL` names (or a test asserting they match)
