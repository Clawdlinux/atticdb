# 0003: AtticDB v0.1, slim scope

Status: Approved after three review rounds (Claude Opus 5.5 and Gemini 4 Argon, independent). Supersedes the scope of [0001](0001-architecture.md). The tape, recovery, writer and session index mechanisms in 0001 still apply, except everything about hash chains, digests, husks, signing, cache, pub-sub and Fast durability.

## Why this document exists

0001 grew features that no user asked for. We cut back to the pain points we have evidence for, and we build one small step at a time. Each step ships, gets two independent reviews, and gets used before the next one starts.

## Evidence we are designing for

Sources: 36 GitHub issues and 4 HN threads (`agent-memory-research.md`), 40 Reddit threads and 6 X searches (`agent-memory-reddit-x.md`). The sample is small and keyword-picked. It is good enough to cut features, not to prove demand.

| # | Pain | Seen in | Step |
|---|---|---|---|
| P1 | A write reports success but is lost | Mem0, Graphiti, LangGraph, MCP memory server | Fixed in M1/M2. Hardened in S1, S2 |
| P2 | "Last N turns" slows down as a session grows | Redis agent memory server | Fixed in M2 |
| P3 | Two processes share one memory file and overwrite each other | MCP reference memory server | Lock done. Server done in S3 |
| P4 | Old and new facts are both treated as true | Mem0, Redis agent memory server, Reddit | S4 |
| P5 | Deletes miss transcripts and caches | Mem0 | S5 |
| P6 | People trust memory they can read and fix by hand | Reddit 2,176-task test (plain markdown wiki won), several threads | S4 (`fact_list`, direct fixes), S5 (export) |
| P7 | Search misses relevant memories | Mem0, Graphiti, Chroma | Deferred. `fact_list` by prefix plus recency first |

Nobody in the sample asked for tamper-evident logs, signed records, hash chains, a Redis-style cache, pub-sub, prefix-cache-aware context assembly, or vector search as a first need. "Provenance" in the sample means "where did this memory come from and what replaced it". That is a data-model feature, covered by facts.

## Who v0.1 is for

A developer running coding agents or a small agent app on one machine or one server. They want memory that never loses a write, stays fast, can be shared by several agent processes, and can be read and edited as plain text.

## Non-goals for v0.1

| Deferred | Evidence that would unblock it |
|---|---|
| Hash chains, signatures, verify tooling | A user or buyer asks for third-party verification of memory contents |
| Cache with TTL, pub-sub, Fast durability | Users of S3 ask for shared scratch state between agents |
| Ranked keyword search (BM25) or a search index | `memory_search`'s newest-first substring scan (D86) is too slow on dogfood data, or its order hides what agents need |
| Vector search | Keyword search measurably misses what users need |
| Physical erasure and compaction | A user needs disk space back or a compliance erase, or log size becomes a measured problem |
| Retention policies | A user asks for expiry |
| PrefixLedger | Never by default. Only with a measured TTFT win |
| Replication, multiple writers, write pipelining | A user needs more than one machine, or a measured throughput need |
| Trust labels | Poisoning shows up in dogfood or a user asks |
| Markdown import | Dogfood shows direct fixes (`fact_set`, `fact_delete`, `forget`) are not enough |
| Hierarchical knowledge base, boards, workflows | S4 key paths with `fact_list(prefix)` cannot express a structure that dogfood needs |
| Container image | A user runs AtticDB as a sidecar and asks for a published image |
| TLS and non-loopback TCP | A user needs to reach AtticDB from another machine and a TLS proxy on loopback does not serve them |

## The model

One append-only log (the tape) holds every write. Everything else is an index rebuilt from the log. Every write is durable: there is no "fast, may be lost" mode.

| Kind | Code | Payload | Purpose |
|---|---|---|---|
| `Turn` | 1 | agent, session, seq, role, meta, content, idem_key? | A message or tool result in a session |
| `Fact` | 2 | key, content, meta, agent (attribution only), source_refs, idem_key?, tombstone flag | A piece of memory that can be replaced or retracted (S4). One per write. `source_refs` must be empty until a later step validates it inside the tenant |
| `Forget` | 3 | selector (session, fact key, or LSN list), all within one tenant | Hides content from every read path (S5) |
| (reserved) | 4 | | |
| `Footer` | 5 | see Frame v2 | Closes a transaction |
| `TenantCreate` | 6 | tenant name | Maps a tenant name to a small id |

## Frame v2

Integrity comes from CRC32C, not cryptography. Every frame is bound to where it sits and every footer to its records, which is what SQLite and Postgres do against misplaced or stale data.

```text
u32 crc32c(segment_id_le || offset_le || bytes [4..len))   location is hashed, not stored
u32 len | u8 kind | u8 version=2 | u16 flags=0
u64 txn | u64 lsn | u64 commit_time_ns | u32 tenant_id
payload
```

Header: 40 bytes, down from 104. `segment_id` comes from the manifest, never from a file name. The location seed catches misdirected writes and frames copied to the wrong place. It does not catch stale frames at a reused offset, because segment ids and offsets are reused after truncation. The footer binding and the tail zeroing catch those.

Footer payload (32 bytes): `u64 txn | u64 first_lsn | u64 synced_lsn | u32 record_count | u32 records_crc`.

- `records_crc` is a CRC32C over the concatenated 4-byte CRCs of the transaction's records. A footer validates only against exactly the records it closed.
- `synced_lsn` is the writer's durable LSN at the moment the footer is built. It says: every LSN up to here was already synced before this footer existed.

### LSN assignment

- Every record frame (`Turn`, `Fact`, `Forget`, `TenantCreate`) consumes exactly one LSN: its LSN is the previous record's LSN plus 1.
- A footer consumes no LSN. Its header LSN equals `first_lsn + record_count - 1`, the last record it closes.
- Txns are dense: each transaction's txn is the previous txn plus 1.
- `TenantCreate` sits inside a normal transaction. Its `tenant_id` is the new tenant's own id. It never appears in a tenant's export.
- The tape's LSN-to-location index is per-segment arrays of offsets (LSNs are dense, so the segment's first LSN plus an array index finds any record), paged like the session index. It replaces today's ever-growing map.

### Recovery rules on top of 0001

- Below the superblock: any bad frame, early end, or missing segment is `CorruptionDetected` (unchanged).
- Above the superblock, recovery looks ahead before dropping data. Let `d` be the first LSN it would drop:
  - It scans forward byte by byte through the rest of the segment and every later manifest segment.
  - A candidate needs a whole valid transaction. Check location-seeded CRCs, dense LSNs, `records_crc`, header fields and footer guards.
  - Its `first_lsn` must be at least `d`. With these checks, a false match is negligible.
  - A validated footer with `synced_lsn >= d` proves corruption of synced data. Return `CorruptionDetected`, never silently truncate.
  - Otherwise the bad frame is a torn tail: truncate, zero, and sync as today, and report the truncated LSN range in the logs and in `/healthz`.
- Guards in both normal verification and lookahead: `previous footer's synced_lsn <= footer.synced_lsn < footer.first_lsn`. The writer sets `synced_lsn` from the LSN it has actually synced, never from the last LSN it wrote. A smaller value is safe; a larger one breaks the proof.
- `d` is the last retained transaction's LSN plus 1. Damaged frame bytes never choose the proof boundary.
- The reported bad LSN is diagnostic only. A recognizable footer reports its last record LSN.
- The scan skips runs of zeros cheaply, because after an ordinary crash it mostly walks preallocated space.
- Soundness (confirmed by both reviewers): every footer in an unsynced group carries the previous group's durable LSN, so no footer can vouch for a torn record in its own group. The only silent truncation left is damage inside the last synced group with no later footer, which I1 states.
- `atticdb recover --truncate-at <lsn>` is the explicit, logged, operator-only escape when the data directory will not open.
  Cuts accept 0 or transaction ends; interior cuts fail with both boundaries. D73 permits dropped-LSN reuse and defines crash-safe ordering.
- The last `commit_time` is recovered from the tape, so `commit_time` stays monotonic across restarts.

v1 frames are rejected. There is no data on disk to migrate.

What we give up: a person with write access to the data directory can edit history undetected. That is true of every mainstream database.

## Steps

Each step is one branch with a written plan, an implementation, two independent reviews, a merge, and real use before the next step.

### S1: frame v2 and cleanup

- Frame v2, footer binding, LSN assignment as above, dense LSN and txn checks, the `synced_lsn` lookahead across segments, `atticdb recover --truncate-at`.
- Per-segment paged LSN arrays replace the tape's ever-growing LSN map.
- Remove chain fields, salts, content digests, husks, `chain_next`, `batch_digest`, chain checks, `Kind::Cache`, `Kind::Redaction`, `Durability::Fast` and the turn `trust` field.
- Renumber kinds as in the model table. Fix the Fact and Forget payload versions now, so later steps only add behavior.
- `commit_time` monotonic and recovered from the tape. Durable LSN stored after the state machine's publish.
- BLAKE3 stays for idempotency digests and checkpoint manifest digests only.
- Done when all tests and both sims pass, including new stale-footer, bit-flip-above-superblock (with and without a later proving footer, across segments), corrupt-length and empty-sync-step cases, and G1 numbers are not worse.

### S2: disk full

- Free-space floor (default 1 GiB or 5%, whichever is smaller), checked in the writer step before `prepare`, together with pre-rolling the segment when the batch does not fit. Below the floor, writes fail with `DiskFull` and `NotCommitted` without touching any state, the engine stays readable, and health reports `read_only`.
- Real preallocation when a segment is prepared, using `rustix` (safe wrappers for Linux `fallocate` and macOS `F_PREALLOCATE`, followed by `set_len` because `F_PREALLOCATE` does not move the end of file). This replaces the "no libc" rule (D34).
- On copy-on-write filesystems (APFS, btrfs) preallocation does not guarantee later writes succeed. The floor is the real guard there. Any write or sync error still poisons the writer.
- Done when the disk-full sim shows no acked loss and no poisoning on a clean floor hit.

### S3: server and MCP

- `atticdb serve` holds the lock. HTTP/JSON on TCP bound to `127.0.0.1:7425` by default. Other addresses need an explicit flag and TLS. S3 has no TLS, so it refuses them. A TLS proxy on loopback covers remote access.
- It also listens on a Unix domain socket, default `<data_dir>/atticdb.sock`, set by flag or config. The socket file is mode 0600, or 0660 with `--unix-socket-group`. Its parent must be owned by the server's user and not writable by group or others. The data directory must be private (0700). Only the lock holder installs the socket, under a `flock` on `<path>.lock`, and a server only removes its own socket. Agents in sandboxes and microVMs reach the host through it: Firecracker forwards guest vsock connections to a host Unix socket, and runc and gVisor containers can share its directory through a bind mount. See `docs/deploy/sandboxes.md`.
- Auth: one token per tenant in a config file that must be mode 0600. The token travels only in the `Authorization` header with the Bearer scheme and is compared in constant time. The tenant comes from the token, never from the request. On TCP the `Host` header must be a loopback name. On the Unix socket `Host` has no meaning and is not checked.
- `LOCK` and `/healthz` carry a per-start instance id. Clients that find the server through `LOCK` use only its Unix socket, check its ownership the way OpenSSH StrictModes does, and trust it only when the ids match.
- `--exit-on-poison` makes a poisoned server exit with code 70 and release the lock. `atticdb mcp` always sets it when it starts a server. A second server on a locked directory exits with code 75.
- Every write endpoint requires `idem_key`. The response carries the outcome (`committed`, `not_committed`, `unknown`) and a `deduplicated` flag. A client never downgrades an outcome. After a transport error or `unknown`, only `committed` replaces `unknown`. A call whose attempts never sent a byte is `not_committed`.
- `GET /v1/window` takes a `max_bytes` budget. Turns are never cut. The response says when older turns were left out.
- `GET /healthz` returns 200 with `{"status": "ok"}` or `{"status": "read_only"}`, and 503 with `{"status": "poisoned"}`. Each body also carries `instance`. Read-only stays 200 on purpose. Only a write can clear it, so a probe must not take the instance out of rotation.
- `atticdb mcp`: stdio adapter. It connects to a running server, or starts one if none is reachable; the loser of the lock race connects to the winner. It generates one `idem_key` per tool call and retries on transport errors and `unknown` with the same key. The model never sees keys. Tools: `memory_append`, `memory_recent`. An auto-started server listens on the Unix socket only. The retry deadline is the one timeout knob, and no attempt, the first included, connects or sends with less than 2 s left.
- A small Python client with the same retry rule.
- Done when two MCP clients writing to one server lose nothing, and a killed server restarts with every acknowledged write. An MCP client in a simulated Firecracker guest, which only reaches the Unix socket, loses nothing either.

### S4: facts

- Key scope is per tenant. Agents namespace keys with prefixes like `agent/x/...` or `repo/<area>/...`. `agent` is attribution metadata, not part of the key. Prefixes are byte prefixes.
- A write carries one fact. A batch with two fact records, or a fact next to a turn, is rejected with `InvalidInput`, so the same key can never appear twice in one batch. `source_refs` must be empty.
- The current value of a key is its newest revision by LSN. A tombstone means no current value. The current LSN is that value's LSN, or 0 when there is none.
- `fact_put(key, content, idem_key, if_lsn?)`: `if_lsn` makes the write conditional on the current LSN, checked by the single writer at prepare after the retry check. `if_lsn = 0` means the key must have no current value. A mismatch returns `Conflict` (HTTP 409 `conflict`), never committed. `if_lsn` is not part of the retry identity.
- `fact_delete(key, idem_key, if_lsn?)`: a tombstone. `fact_get` then returns not found. History shows it.
- `fact_get`, `fact_history` (newest first, at most `fact_history` revisions, `truncated` when older ones exist), `fact_list(prefix, limit)` with an `after` cursor. A list visits at most 1,024 index entries per call. `next` is the last key the walk finished with, so paging always advances. A byte budget always returns the first entry. The read it cut counts in `fact_reads`.
- The fact index holds LSN pointers, tombstone bits and a per-key dropped bit, never content. It is capped by `max_facts` keys (global, tombstones keep their slots) and `fact_history + 2` revision pointers per key, and it is checkpointed. A lowered `max_facts` makes open fail until the cap is raised, as `max_sessions` does. Reads use the newest revision at or below the durable LSN they observed.
- HTTP keeps keys out of paths: `POST /v1/facts/put`, `POST /v1/facts/delete`, `GET /v1/facts/get`, `GET /v1/facts/history`, `GET /v1/facts/list`. A missing fact is `{"fact": null}`.
- MCP tools: `fact_set` (with `delete: true` to remove), `fact_get`, `fact_list`. The model never sees `if_lsn`.

### S5: forget and export

- `forget(selector, idem_key, up_to_lsn?)` by session, fact key, or LSN list, all resolved inside the caller's tenant. It covers records at or below the forget's own LSN, or at or below `up_to_lsn` when given, so later writes are never hidden and a retry cannot move the cutoff.
- Named "hide, not erase" in the API and docs. Forgotten bytes stay in segment files until compaction exists. No compliance claims.
- Idempotent retries of forgotten writes return the original reply and never rewrite content.
- `GET /v1/export?format=markdown` reads one consistent durable LSN and writes one readable file per session plus one for facts. The CLI `atticdb export` is a client of the server.
- Markdown import is deferred (see non-goals). Hand fixes go through `fact_set`, `fact_delete` and `forget`.
- Note: idempotency digests in checkpoints are unsalted BLAKE3 of payloads. Someone with disk access could confirm a guess of forgotten content. Documented.

### S6: dogfood

- Use AtticDB as the memory for our own coding agents for 2 weeks.
- Track lost writes, slow reads, wrong recalls, and whether agents actually call the MCP tools.
- Choose the next step from what breaks, using the deferred table.

## Decisions from review rounds 1 and 2

| Question | Decision |
|---|---|
| Logical-only forget in v0.1? | Yes, named "hide, not erase", with I10's coverage rules |
| Facts per tenant or per tenant and agent? | Per tenant. Prefixes for agent-local facts |
| Per-tenant token in a config file? | Yes for loopback, with the S3 hardening. Non-loopback needs TLS and an explicit flag |
| Libc rule | Replaced: `rustix` allowed for preallocation and free-space checks |
| Write pipelining | Out of v0.1. Not needed for the measured G1 numbers |
| Group rule vs `synced_lsn` | `synced_lsn` in the footer: no counter, immune to empty sync steps (review round 2) |
| Markdown import | Deferred. Direct fixes cover the evidence (review round 2) |
| Unix socket in S3? | Yes. It is how trusted sandboxed and microVM agents reach the host (owner, 2026-10-21, D75). By default the harness holds memory instead (D79) |
| Run AtticDB inside a sandbox? | No. Host or sidecar. A guest's storage may drop flushes (Firecracker `Unsafe`) or vanish (gVisor overlay) |
| TLS in S3? | No. Non-loopback TCP is refused. A loopback TLS proxy covers remote access |
| Multi-fact batches? | No. One fact per write, so retries keep one `(tenant, key)` scope (D76) |
| `if_lsn` in MCP? | No. The model holds no reliable LSN. Later writes win, which is what a correction means |
| `if_lsn = 0` on a deleted key? | Matches. Zero means "no current value", the same thing `fact_get` reports |
| `source_refs` in S4? | No. Non-empty refs are rejected. Checking them needs tape reads in prepare and touches S5 forget (owner, 2026-10-22) |
| Per-tenant fact cap? | No. Global `max_facts`, like `max_sessions`. Tombstones keep their slots (owner, 2026-10-22) |
